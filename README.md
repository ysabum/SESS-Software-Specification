# Project 2 README

## Significant Changes and Deviations
The SESS Software Requirements Specification document was reorganized into a format that is easier for both developers and generative AI systems to read. The primary changes include:

- Reorganized the document into the required AI-friendly specification structure
- Converted existing goals into a concise numbered business goal list
- Consolidated the subject facet and object model into a simplified domain model consisting of actors and objects
- Renumbered all functional requirements using unique identifiers (FR1 to FR-001).
- Renumbered all acceptance criteria (behavior-driven scenarios) using unique identifiers (BDS1 to AC-001) and associated each acceptance criterion with its corresponding functional requirement
- Removed sections unrelated to the implementation (e.g., wireframes, navigation paths, glossary, introduction, context analysis, and dynamic models)

These changes were made to improve requirement traceability, remove ambiguity with what goal is associated with which functional requirement, and make the overall document easier for an AI to parse through.



## Software Design and Development References
The primary reference used was the SESS Software Requirements Specification from Project 1. 



## AI Use
- AI was only used to improve the consistency of the requirement numbering (as mentioned in *Significant Changes and Deviations*) and to verify that business goals, functional requirements, and acceptance criteria remained aligned.
